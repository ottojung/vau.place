notes from a logic question

A small experiment with addition on Rabin's tree

I was reading about Rabin's tree theorem and became curious about a fairly ordinary question: what happens to decidability if the tree is given one more operation? I tried to make that operation resemble addition. These are the notes from where that question led me.

the tree→the logic→the question→addition→powers
context

Which tree?

The tree here is the complete infinite binary tree. A convenient way to describe it is T = {0,1}*, the set of all finite binary strings. The empty string ε is the root. Every node w has exactly two children, w0 and w1. 

             ε
           /   \
          0     1
        /  \   /  \
       00  01 10  11
       ...        ...

So a node is not a number and it does not come with an obvious arithmetic interpretation. It is just a position in an infinitely deep, but locally very simple, structure.

There is also a natural order on the nodes. Write x ≼ y when x is a prefix of y. Geometrically, this means that x is an ancestor of y. Unlike the ordinary order on numbers, this is only a partial order: 00 and 11, for example, are incomparable.

context

Which logic?

The logic in Rabin's theorem is monadic second-order logic, usually abbreviated MSO.

Ordinary first-order logic lets us quantify over individual nodes. We can say things such as “there is a node whose left child has some property.” MSO additionally lets us quantify over sets of nodes. A variable like X can stand for an arbitrary set of positions in the tree, and formulas can ask whether x ∈ X.

That extra kind of variable is useful on a tree because sets can describe extended objects: paths, regions, inductively closed collections of nodes, and so on. For example, MSO can recover the ancestor relation from the child relations. One way to say that x is an ancestor of y is: every set which contains x and is closed under taking children must also contain y.

When logicians talk about the MSO theory of this tree, they mean all MSO sentences which are true in it. Saying that the theory is decidable means that there is an algorithm which can take any such sentence and eventually answer whether it is true or false.

motivation

Why Rabin's theorem is interesting here

Rabin proved that the MSO theory of this complete infinite binary tree is decidable. This is already a useful combination: the structure is infinite, and the logic can quantify over arbitrary sets of nodes, but there is still an algorithm for deciding every sentence.

Infinite trees are also a natural way to represent branching behaviour. A node can stand for a state or a finite history, and its children for possible next steps. MSO is closely connected with tree automata, so questions about formulas on trees can often be turned into questions about automata. Rabin's theorem sits at the centre of that connection.

For me, a decidability theorem like this also raises a boundary question. A structure is presented in some language: here we have the two child operations. If we add another relation or operation to that language, the theory may stay decidable, or it may not. Trying small extensions is one way of understanding what the original theorem is really sensitive to.

Arithmetic is a natural candidate to test in this setting. Many undecidability arguments in logic work by finding, or interpreting, enough arithmetic inside another structure. So I wondered what would happen if the tree were equipped with something that behaved a little like addition.

This was not a particularly precise question yet. There is no standard “addition of tree nodes.” The experiment was to see whether a few natural requirements could make the question precise.

first attempt

What should addition mean on a tree?

I first thought about familiar algebraic laws: associativity, commutativity, perhaps a distinguished zero at the root. But these do not capture much of what makes ordinary addition feel positive.

On any countable set one can invent rather uninteresting associative operations. Even commutativity and an identity do not force repeated addition to move anywhere. For example, after choosing an arbitrary total order of the tree nodes with ε first, the max operation is associative, commutative, has ε as an identity, and is idempotent. It satisfies several familiar-looking laws while doing nothing that resembles numerical growth.

So I tried to express growth using the tree order itself. Since the ancestor relation is already MSO-definable from the child relations, using it in the condition does not add another primitive to the structure.

failed condition

Ordinary positivity is too strong

For positive integers, adding two nonzero numbers gives something strictly larger than either input:

x, y > 0  ⇒  x + y > x and x + y > y.

The direct tree analogue would require x+y to be a strict descendant of both x and y. That cannot work. If x and y lie on different branches, they have no common descendant.

The failed condition was useful because it showed that I was mixing up two ideas: numerical growth and movement upward in a particular order. The latter is incompatible with branching.

weaker condition

A weaker version of positive growth

I then tried the following condition. Let ε be the root:

x, y ≠ ε  ⇒  ¬(x + y ≼ x) and ¬(x + y ≼ y).

The sum is not required to be above either argument. It may land on an incomparable branch. The only requirement is that it does not collapse to, or below, either summand in the ancestor order.

I will call this positive growth here. The name is only local to this post; I am not claiming it as standard terminology.

At this point I was still thinking of the condition as a way to rule out uninteresting tree operations. What mattered in the end was one simple consequence: a non-root element cannot be idempotent.

consequence

Repeated addition gives distinct powers

Assume now that + is associative and satisfies the growth condition. Pick a non-root node a. Associativity makes the repeated sums unambiguous:

a,  a² = a+a,  a³ = a+a+a,  …

Positive growth rules out x+x=x for non-root x, because equality would in particular imply x+x ≼ x.

Suppose two powers of a were equal: a^i = a^j for some i<j. The sequence of powers would then become periodic, so the subsemigroup generated by a would be finite. A standard fact about finite monogenic semigroups says that such a semigroup contains an idempotent power. That contradicts the growth condition.

Therefore a, a², a³, … are all distinct. And associativity gives

a^m + a^n = a^(m+n).

So, just inside the powers of one element, the operation already behaves like addition on the positive integers.

logic again

MSO can define that sequence

Having a copy of the positive integers inside the structure is not by itself enough for an interpretation argument. The logic also has to be able to pick it out.

This is where the set quantification in MSO is useful again. Fix a and consider the step x ↦ x+a. Reachability along this step can be expressed by quantifying over all sets closed under it: 

Reach_a(x, y) :=
  for every set X,
    if x ∈ X
       and X is closed under u ↦ u+a,
    then y ∈ X

Therefore MSO can define the generated set

D_a = {a, a², a³, …}.

Restricted to D_a, the operation is exactly addition of exponents. In other words, the expanded tree interprets (N>0,+).

The full MSO theory of (N,+) is undecidable. Hence an associative operation satisfying the positive-growth condition makes MSO(T,S0,S1,+) undecidable as well.

In particular, such an operation cannot already have been MSO-definable from the original tree structure: if it were, adding its symbol would not take us outside Rabin's decidable theory.

a more general way to read the argument

Most of the tree is no longer used

When I rewrote the argument in this form, I noticed that the tree has a fairly limited job. Its order supplied one convenient condition that prevents powers from collapsing. Once the powers are known to be distinct, the rest of the argument only uses the associative operation and MSO.

The same reasoning therefore gives a more general statement:

If a semigroup contains an element with infinitely many distinct powers, then its full monadic second-order theory is undecidable.

Such an element is usually called an element of infinite order. Its generated subsemigroup {a,a²,a³,…} is a copy of (N>0,+), and MSO can define that subsemigroup by the same reachability argument.

There is a small technical point here: a particular infinite-order element need not be named in the language. MSO can nevertheless express that the orbit generated by a has no cycle, so a reduction can existentially choose a suitable a and then relativize its quantifiers to the generated orbit.

the parameter detail

Let D_a(x) say that x is reachable from a by repeatedly multiplying on the right by a. A finite orbit eventually repeats and therefore contains a directed cycle. If all powers are distinct, no such cycle exists.

This gives an MSO formula expressing that a has infinite order. A sentence about (N>0,+) can then be translated by existentially choosing such an a and restricting its number and set quantifiers to D_a.

A small corollary

A finite monogenic semigroup contains an idempotent. Therefore a nonempty semigroup with no idempotents cannot have an element with only finitely many powers. Every element has infinite order, and the same MSO undecidability argument applies.

I do not know whether this exact formulation is standard. A limited literature search turned up the individual ingredients and nearby results about monadic and finite-subset theories of semigroups and monoids, but not this statement under this wording. I would not take that as evidence of novelty; the argument is short enough that I expect it is known in some form or under different terminology.

What I found useful about the exercise was more modest. I began with a question about the boundary of one decidability theorem, tried to formalize the vague phrase “addition should grow,” and then saw which part of the setup was actually doing the work. The tree motivated the condition, but the repeated powers carried the arithmetic.

  1. Michael O. Rabin, “Decidability of Second-Order Theories and Automata on Infinite Trees” (1969). The theorem that motivated the question: the monadic second-order theory of the complete infinite binary tree is decidable. DOI
  2. Wolfgang Thomas, “Languages, Automata, and Logic” (1997). A broad introduction to the connection between monadic second-order logic and automata, including the role of trees. PDF
  3. Raphael M. Robinson, “Restricted Set-Theoretical Definitions in Arithmetic” (1958). A classical source around arithmetic definability with restricted set quantification. DOI
  4. Julia Robinson, “Definability and Decision Problems in Arithmetic” (1949). A classical reference for definability results which connect divisibility and multiplication in arithmetic. DOI
  5. Monogenic semigroups. The finite case is eventually periodic and contains an idempotent in its cyclic part. This is the small algebraic fact used to show that the powers above cannot repeat. Encyclopedia of Mathematics
  6. Sergey Dudakov, “On Undecidability of Finite Subsets Theory for Torsion Abelian Groups” (2022). This studies a different logical theory, but is nearby in spirit: arithmetic interpretations in finite-subsets theories of algebraic structures. DOI
